# Capability Status Definitions

本文件定义 `oh-my-deepseek-harness` 对外宣称能力的状态分级。所有对外文档（README、产品页、能力矩阵）中的能力说明必须使用此处定义的五个状态之一，并链接到对应证据。

## 状态定义

| 状态 | 含义 | 宣称边界 | 证据要求 |
|------|------|---------|---------|
| **Stable** | 已实现、已通过契约测试、有真实 E2E 或运行时证据 | 可对外承诺稳定可用 | 契约测试 + 运行时证据（E2E 或真实调用） |
| **Beta** | 已实现、有单元测试，但真实 Hermes E2E 尚未完成或在真实环境验证不足 | 可对外宣称核心功能可用，明确标注验证边界 | 单元/契约测试 + `COMPAT-001` 计划 |
| **Experimental** | 已实现、有基础测试，但行为可能随版本调整，或依赖特定环境 | 可对外宣称存在，标注"实验性" | 单元测试 + 已知限制 |
| **Degraded** | 已实现但有已知降级（如 API 限制导致的替代实现） | 可对外宣称存在，必须说明降级点 | 单元测试 + 降级说明 |
| **Removed** | 已移除或不可实现，仅作历史记录 | 不得宣称可用 | 移除/不可行记录（spike 或决策） |

## 分级判定规则

1. 能力必须能对应到 `docs/testing/evidence/` 下的证据文件，否则不得宣称；
2. 绝对化表述（唯一、零副作用、永不冲突、自动学习）一律禁止，除非有对应测试或运行时证据；
3. 真实 Hermes E2E 未完成前，涉及与 Hermes 集成面的能力最高只能标 **Beta**；
4. 存在 API 层限制而被替代实现的能力，标 **Degraded** 并注明降级点；
5. 无法通过 API 实现或已移除的能力，标 **Removed**，仅作历史记录。

## 证据来源

- 契约测试：`tests/test_*.py`（`TC-*` / `XF-*` 用例）
- 运行时证据：`docs/testing/evidence/*.md` 中的可复现运行记录
- 真实 E2E：`COMPAT-001`（尚未完成，见 `docs/testing/evidence/COMPAT-000.md`）

- M4/G3 后，所有能力行状态必须与本文件一致，且证据链接可验证。
