## 1. 可证伪假设

假设：公开信息和已连接工具足以证明精确 PyPI 项目名、维护者权限、2FA 与 Trusted Publisher 均已就绪。

核对结果：假设不成立。

- 精确名称的公开搜索没有返回已索引项目，但搜索缺失不能证明名称可注册或归属；
- 已连接工具无法读取 PyPI 私有账户、角色、2FA、恢复代码或 Trusted Publisher；
- 因此不能形成“PyPI 已可发布”的可信结论。

## 2. 公开检索结论

```text
exact project search: no indexed `oh-my-deepseek-harness` result observed
name availability: NOT PROVEN
name ownership: NOT PROVEN
maintainer role: NOT PROVEN
2FA: NOT PROVEN
Trusted Publisher: NOT PROVEN
```

另有公开包 `deepseek-harness`，但它是不同项目，不属于本仓库，不能作为替代身份或发布目标。

## 3. 固定渠道决策

```text
First Public Beta mandatory channel: GitHub Release
First Public Beta PyPI channel: DISABLED
```

只有在以下证据完整后，PyPI 才能启用：

- 精确 normalized name；
- Owner/Maintainer 角色；
- 所有发布账号启用 2FA；
- Trusted Publisher 绑定精确 repo/workflow/environment；
- OIDC/最小权限，无长期 Token；
- 发布预演与 Release Checklist 通过；
- `BETA-001` 执行时再次获得明确发布授权。

## 5. Acceptance 判定

REL-005 允许两种完成结果：

1. publish-ready prerequisites 经过认证验证；或
2. 明确选择 GitHub-only Beta，并关闭未验证的 PyPI 路径。

本次采用结果 2。它是可执行的安全默认值，不是对名称可用性的推断。
