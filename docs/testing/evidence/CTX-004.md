## 3. Implemented invariants

1. Compressor state is isolated per Session for:
   - `_previous_summary`;
   - `_ineffective_compression_count`;
   - `_summary_failure_cooldown_until`.
2. Shared compressor activation is serialized by an `RLock`; Session identity remains ContextVar-scoped.
3. Candidate transaction state is snapshotted before generation.
4. Exception mutations, invalid summaries, integrity rejection and non-reducing candidates restore rejected candidate state.
5. A real provider failure may retain only the newly established per-Session anti-thrashing cooldown; rejected summary history and counters still roll back.
6. Provider/current token counts are used only for the compression threshold decision.
7. Candidate acceptance compares one deterministic estimator on:
   - the caller's actual original messages;
   - the final reconciled candidate.
8. Acceptance requires `deterministic_after_tokens < deterministic_before_tokens`.
9. Rollback returns the exact original list object; accepted compression returns a new object.
10. No rejected summary can enter a later Provider prompt.
11. Protected messages, hard constraints, latest user request and Tool Call/Result pairs remain intact.
12. Metrics expose only counts; no message content or real user data is emitted.
