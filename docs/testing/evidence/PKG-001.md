## 1. 目标

把生产 Python 实现收敛到唯一 `src/` 布局：

```text
src/deepseek_harness/
src/deepseek_context/
src/harness_server/
```

旧 `plugins/**` 与 `mcp/harness_server/**` 不保留第二份业务实现，只保留 Hermes/source-checkout 兼容转发。

## 2. 包契约

- Python distribution：`oh-my-deepseek-harness==3.0.0b1`；
- package discovery：仅 `src/`；
- Hermes pip entry-point group：`hermes_agent.plugins`；
- entry points：
  - `deepseek-harness = deepseek_harness`；
  - `deepseek-context = deepseek_context.plugin`；
- package data：
  - Harness `plugin.yaml`、`strategies.yaml`；
  - Context `plugin.yaml`、`config.yaml`；
  - Server `config.yaml`。

Hermes v0.19.0 会对 entry point 执行 `ep.load()`，取得模块后调用模块的 `register(ctx)`。本布局与该正式契约一致。

## 3. 迁移边界

保持不变：

- 10 个目标 Tool / 9 个当前 Runtime Tool；
- Hook、Schema、API、DB 和领域逻辑；
- Plugin Manifest 版本；
- Python 3.10–3.12 package/core CI；
- Hermes v0.19.0 完整集成仅 Python 3.11–3.12。

必要路径修正：

- Server 启动由源码脚本相对路径改为 `python -m harness_server.server`；
- Intent strategies 使用 `importlib.resources` 从 wheel 资源读取；
- `tests/conftest.py` 删除 `sys.path` 注入与下划线 symlink；
- COMPAT/G0 静态探针改读 `src/` canonical source。

## 4. 制品验证

`tests/test_package_artifact.py` 必须验证：

1. 从 `git archive HEAD` 构建 wheel；
2. wheel 包含三个 package 与全部 YAML/config resources；
3. wheel 不包含 `plugins/` 或 `mcp/` 生产副本；
4. 临时 venv 从 wheel 安装；
5. 在仓库外导入 `deepseek_harness`、`deepseek_context`、`harness_server`；
6. 两个 Hermes entry points 可加载为模块；
7. Server Tool 启动目标为 module，不使用 `_SERVER_SCRIPT`；
8. 旧目录仅保留薄适配文件。
