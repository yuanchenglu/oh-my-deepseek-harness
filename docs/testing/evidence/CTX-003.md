## 1. Problem statement

Compression lacked a canonical identity and reconciliation layer. Hard constraints could be summarized instead of preserved verbatim, latest requests had no exact-once identity contract, and Tool Call/Result pairs could be replaced by stubs or split by compression.

## 2. TDD evidence

`XF-CTX-003` was removed and ordinary regressions require:

- hard constraints preserved verbatim under one stable ID;
- latest user request preserved verbatim exactly once;
- complete Tool Call/Result pairs preserved together exactly once;
- all generated IDs non-empty、unique and stable for equivalent input;
- 64 seeded property sequences with zero counterexamples.

Run #214 failed on Python 3.10、3.11、3.12. No skip、assertion weakening or replacement XFAIL was used.

## 3. Implementation

`src/deepseek_context/_message_integrity.py` provides:

1. deterministic canonical IDs derived from message payload plus occurrence index;
2. preservation of existing non-empty unique IDs;
3. protected classification for hard constraints、latest user message and complete Tool pairs;
4. post-compression restoration of protected messages from the canonical original copy;
5. exact-once ID reconciliation and original-order insertion;
6. removal of sanitizer stubs when the canonical protected Tool result exists;
7. deterministic IDs for generated summary messages.

The public engine assigns stable IDs before candidate compression, retains CTX-002 transaction safeguards, removes CTX-001 duplicate Merge tails, then reconciles protected messages.
