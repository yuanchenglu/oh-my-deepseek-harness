## 2. 新增治理入口

### Security

`SECURITY.md` 定义：

- GitHub Private Vulnerability Reporting 为首选私密渠道；
- 禁止在公开 Issue、PR、Discussion、commit、日志或测试制品中披露漏洞细节和敏感数据；
- Experimental Preview、Beta 与 Stable 的支持范围；
- P0/P1/P2/P3 严重度与 Release Gate 影响；
- 3 个工作日确认、7 个工作日初步分级、调查期间至少每 7 个工作日更新的维护目标；
- 协调披露、不可变 Tag/Artifact、Safe Harbor 意图和维护者数据处理要求；
- Public Beta/Stable 前必须从非维护者视角确认 Private Vulnerability Reporting 可用。

这些时间是维护目标，不是合同 SLA。

### Issue Forms

- `config.yml`：关闭 blank Issues，并将安全报告路由至私密 Advisory；
- `bug_report.yml`：非安全缺陷表单，包含 Work/Requirement/Test、当前/期望、复现、环境、风险、数据影响、兼容迁移、回滚、证据和不在范围；
- `work_item.yml`：计划 Work ID 表单，包含依赖、可证伪假设、授权路径、三层验证、风险、迁移、恢复和追踪。

两个公开表单均明确禁止提交安全漏洞、真实秘密和私人用户数据。

### Pull Request

保留原执行模板，新增：

- 私密安全报告警告和 `SECURITY.md` 链接；
- 不披露 Private Advisory 内容的确认项；
- Release surface 变更必须审查 `docs/release/RELEASE_CHECKLIST.md`；
- 协调披露完成前保持安全修复信息私密。

### Release Checklist

Checklist 覆盖：

- 决策记录和 Gate Evidence；
- Work/Requirement/Test/Issue/PR/Commit/Evidence 追踪；
- Branch Ruleset 与 Required Check 名称；
- 版本、制品、hash、SBOM、provenance；
- Python/OS/Hermes 兼容；
- 安装、诊断、升级、卸载；
- Tool/Context/Session/Plan/Memory/Checkpoint 不变量；
- Security、Privacy、Dependency、License；
- Migration、Backup、Rollback；
- G3 RC 与最终不可变 Beta Tag 顺序；
- 发布后 Failure Ledger 和 G4/G5。

所有项默认未勾选，本文件不声明任何 Gate 已通过。

## 3. 结构验证

```bash

import yaml

root = Path('.')
forms = [
    root / '.github/ISSUE_TEMPLATE/config.yml',
    root / '.github/ISSUE_TEMPLATE/bug_report.yml',
    root / '.github/ISSUE_TEMPLATE/work_item.yml',
]
for path in forms:
    doc = yaml.safe_load(path.read_text(encoding='utf-8'))
    assert isinstance(doc, dict), path

for path in forms[1:]:
    doc = yaml.safe_load(path.read_text(encoding='utf-8'))
    assert all(key in doc for key in ('name', 'description', 'title', 'labels', 'body')), path
    assert isinstance(doc['body'], list) and doc['body'], path

print('issue-form-yaml: PASS')
PY
```
