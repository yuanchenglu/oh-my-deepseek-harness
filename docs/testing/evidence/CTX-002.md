## 1. Problem statement

The base Context Engine treated a missing summary as usable compressed output:

```text
summary failure
  → static "[Earlier context summary unavailable]" placeholder
  → compressed middle messages discarded
  → placeholder + protected tail returned
```

A timeout or exception raised directly by an injected/provider summary function could also escape `compress()`. Both behaviors violate the lossless fallback contract.

## 2. TDD evidence

`XF-CTX-002` was removed and replaced by ordinary regressions covering:

1. provider timeout;
2. provider exception;
3. `None`, empty and whitespace-only summary;
4. malformed/missing-key provider response.

Every case requires:

- return the exact original list object;
- preserve every message, nested content and original ordering;
- leave the input sequence unchanged;
- exclude the static unavailable-summary placeholder;
- prevent simulated Secret and prompt fragments from appearing in logs.

Run #207 failed on Python 3.10、3.11、3.12 after the XFAIL removal. No skip、weakened assertion or replacement XFAIL was used.

## 3. Implementation

The canonical exported `DeepSeekContextEngine` now treats summary generation as a compression transaction:

1. capture the active `generate_summary` implementation;
2. serialize the short interception boundary with a per-engine `RLock`;
3. execute base compression against a deep copy of the message sequence;
4. catch summary-call exceptions without logging exception text;
5. classify non-string、`None`、empty and whitespace-only results as failures;
6. restore the original summary implementation in `finally`;
7. on any summary failure, return the original input list unchanged;
8. on success, continue through the existing CTX-001 exact Merge-tail integrity guard.

Only `src/deepseek_context/_public_engine.py` changes production behavior. Provider selection、request construction and later Context policies remain unchanged.
