## 1. Problem statement

The base engine converted failed summary generation into destructive compression: a static unavailable-summary placeholder replaced the compressed region, and exceptions from injected/provider summary calls could escape `compress()`. Both paths risked history loss.

## 2. TDD evidence

`XF-CTX-002` was removed and replaced by ordinary regressions for timeout、provider exception、`None`/empty/whitespace output and malformed/missing-key responses.

Every case requires the exact original list object, byte-equivalent content/order, no input mutation, no placeholder and no simulated Secret/prompt fragment in logs.

Run #207 failed on Python 3.10、3.11、3.12. No test was skipped、weakened or converted back to XFAIL.

## 3. Implementation

The canonical exported `DeepSeekContextEngine` now treats summary generation as a transaction:

- capture the active `generate_summary` implementation;
- serialize temporary interception with an instance `RLock`;
- run candidate compression on a deep copy;
- catch exceptions without logging exception text;
- treat non-string、`None`、empty and whitespace-only output as failure;
- restore the original summary function in `finally`;
- return the original input list unchanged on failure;
- preserve the successful path and CTX-001 exact Merge-tail guard.

Only `src/deepseek_context/_public_engine.py` changes production behavior.
