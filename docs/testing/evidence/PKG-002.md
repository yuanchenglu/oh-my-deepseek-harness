## 1. 目标

建立可验证的依赖边界，并关闭 `XF-DEPS-001`：

| Variant | Direct dependency contract | Advertised import surface |
|---|---|---|
| base | `PyYAML`, `httpx` | `deepseek_harness` |
| context | base + `openai` | `deepseek_context` |
| server | base + `fastapi`, `uvicorn`, `pydantic` | `harness_server` |
| all | context + server | 三个公共 package |
| dev | all + `pytest`, `pytest-cov`, Python 3.10 的 `tomli` | 开发/测试 |
| mcp | server 的过渡兼容 alias | 与 server 相同 |

所有依赖均有主版本上界，避免公开 Beta 在未审查情况下吸收破坏性主版本。

## 2. Hermes 宿主边界

Hermes Agent v0.19.0 是完整产品宿主，要求 Python `>=3.11,<3.14`；项目 package/core 仍支持 Python 3.10–3.12。因此 Hermes 不作为 base 或 context extra 的无条件 Python dependency。

Context 包采用以下边界：

- 真实 `DeepSeekContextEngine` 实现保持在 `src/deepseek_context/_engine.py`；
- 无 Hermes 的 clean environment 可以 import package、读取 metadata 和验证 OpenAI extra；
- `HERMES_CONTEXT_AVAILABLE` 明确表示真实宿主是否存在；
- `deepseek_context.plugin.register(ctx)` 在缺少 Hermes 时明确抛出 RuntimeError；
- 真实 discovery、selection、lifecycle 和 Tool E2E 仍由 `COMPAT-001` 负责。

这不是无 Hermes 运行 Context Engine 的承诺，也不伪造兼容性。

## 3. Clean-install 矩阵

`tests/test_package_dependencies.py` 必须：

1. 从当前分支构建 wheel；
2. 分别创建 base/context/server/all 四个全新 venv；
3. 通过 wheel direct reference 安装对应 extra；
4. 使用 `python -I` 在隔离模式下执行 import probes；
5. base 环境确认 `openai/fastapi/uvicorn/pydantic` 不存在；
6. context 环境确认 `openai` 存在、Server 依赖不存在，且无 Hermes 注册明确失败；
7. server 环境确认 FastAPI/Uvicorn/Pydantic 与 Server imports 成功、`openai` 不存在；
8. all 环境确认三个公共 package 和全部运行依赖成功；
9. metadata 检查 `all=context∪server`、`mcp=server`、`dev⊇all`。

所有 venv 使用临时 HOME、禁用 user site，不读取真实 `~/.hermes`。
