## 1. Problem statement

The Merge path assembled the protected tail twice:

```text
head
+ [summary merged into tail[0]]
+ tail[1:]
+ tail
```

The result duplicated tail message IDs and contents, violating ordering and uniqueness invariants and creating a P0 context-integrity defect.

## 2. TDD evidence

`TC-CTX-003` was removed from strict XFAIL and converted into an ordinary regression that requires:

1. protected tail IDs appear exactly once;
2. IDs preserve source order;
3. each protected tail content appears once.

Run #197 failed on Python 3.10、3.11、3.12 after the XFAIL removal. The failure was not hidden, skipped or weakened.

## 3. Implementation

The canonical exported `DeepSeekContextEngine` now applies an exact Merge-integrity guard after the base compression result.

The guard acts only when all conditions are met:

1. a message contains the exact Context summary merge marker;
2. the logical original first tail message can be reconstructed by removing that marker prefix;
3. a later message structurally equals that reconstructed first tail message;
4. the complete first and second tail sequences are structurally identical.

Only the exact second sequence is removed. This is not generic deduplication.

Changed production files:

- `src/deepseek_context/_merge_integrity.py`；
- `src/deepseek_context/_public_engine.py`；
- `src/deepseek_context/__init__.py` public export boundary。

## 4. Negative safety boundaries

Permanent tests prove:

- exact full Merge duplicate sequence is removed;
- ordinary intentional repeated messages remain unchanged;
- incomplete or ambiguous duplicate-looking sequences remain unchanged;
- non-Merge compression behavior is not deduplicated by content or ID.

The implementation does not inspect or mutate real HOME、DB、Memory、Secret or provider state.
