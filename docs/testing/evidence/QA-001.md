## 1. Problem

测试只有单一 `pytest` 通道，无法区分"纯单元/契约"（fast）、"受控进程/制品"
（integration）与"最终矩阵+证据"（release）。慢 CI 与假绿风险高（CR-P2-003/004）。

## 2. Implementation

- `Makefile`：新增 `test-fast` / `test-integration` / `test-release` 三个目标，
  且有顶层 `test` 聚合三者。
- `scripts/test_fast.sh`：16 个纯单元+契约测试文件，无网络/真实 HOME/API。
- `scripts/test_integration.sh`：12 个受控进程/制品测试文件（Server E2E、
  install、lifecycle、doctor、supervisor、context properties）。
- `scripts/test_release.sh`：6 项最终矩阵+证据+known-defect gate（release
  readiness、package artifact/dependencies、g0 gate、gate_v2、compatibility）。
- `.github/workflows/ci.yml`：新增 `qa-fast` job 在 CI 上验证 fast 通道。
- `tests/test_qa_channels.py`：通道存在性 + 文件集合两两非重叠 + fast 无进程
  依赖断言（QA-001 通道验证的授权例外）。

## 3. 本地验证

- `tests/test_qa_channels.py`：4 passed
- `bash scripts/test_fast.sh`：234 passed（7.11s）
- `bash scripts/test_integration.sh`：本地环境 8 failed / 4 error —— 均为既有
