## 1. 交付范围

INS-002 建立一个结构化、只读、可机器消费的 Doctor：

```text
deepseek-harness doctor [--json]
  → one DoctorReport
  → human renderer or one JSON object
  → fixed exit class
```

Doctor 检查：

- Python package/core 支持范围；
- Hermes executable、版本 `0.19.0` 与 Python `3.11–3.12` 完整支持组合；
- 必需 Python runtime modules；
- packaged Harness Plugin / Context Plugin adapters；
- managed config schema、runtime 与 privacy 安全默认；
- Server state、PID ownership、configured port、`/health`、`/ready`、`/version`；
- SQLite DB 只读打开；
- Provider credential presence，但不输出 Secret；
- data/config/runtime/log/adapter POSIX 私有权限。

固定退出码：

| Exit | 语义 |
|---:|---|
| `0` | 全部检查通过 |
| `1` | 一般环境/部署/状态失败 |
| `3` | 缺 Python/Hermes runtime dependency 或无效基础配置 |
| `4` | unmanaged port conflict |
| `5` | unsupported Python/Hermes/config support matrix |

## 2. 严格 Code Review 发现与修复

| 严重度 | 发现 | 修复与验证 |
|---|---|---|
| P0 | Doctor 若直接调用 `Supervisor.status()`，会创建 data/runtime/log 与 lock，违反只读契约 | Doctor 直接只读 state、ownership、socket 和 HTTP probes；空 HOME before/after snapshot 完全一致 |
| P0 | Python 3.10 package/core 绿色可能被误报为完整 Hermes 支持 | Hermes `0.19.0 + Python 3.10` 固定退出 5，明确提示 Python 3.10 仅 package/core |
| P0 | unmanaged listener 可能被误认成 Harness 或触发进程操作 | 无 managed state + port open 固定 exit 4；不探测 Harness endpoints、不发送信号、不启动双进程 |
| P0 | Linux zombie 被 `kill(pid, 0)` 误判为 live，清理时 ownership 消失并拒绝完成 | `pid_is_alive()` 使用 `/proc/<pid>/stat` 将 `Z` 视为 exited；新增无信号 zombie regression，保留 foreign/PID-reuse fail-closed |
| P1 | human/JSON 若分别计算可能产生状态与退出码漂移 | 两种输出共用同一个 immutable `DoctorReport`；snapshot/parity 测试 |
| P1 | 诊断输出可能泄露 API Key 或 managed absolute paths | details 只输出逻辑 check、版本、host/port、文件名和 redacted presence；测试断言 Secret 与临时 HOME/data root 不出现 |
| P1 | DB/Provider/permission 检查可能隐式修复环境 | DB 使用 SQLite `mode=ro`；Provider 只检查 presence；permissions 只读 stat，无 chmod/write |
| P2 | Doctor 单元/快照测试若混入 INS-001 大型事务 E2E，会混淆 Work ID 所有权 | Issue #23 记录测试路径范围变化，新增独立 `tests/test_doctor.py`，不改变产品契约 |
