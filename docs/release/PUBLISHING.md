# Publishing Policy

- Work ID: `REL-005`
- Decision date: 2026-07-28
- Current decision: **GitHub Release is mandatory; PyPI is disabled for the first Public Beta until authenticated publishing prerequisites are verified.**
- Target release identity: Git/GitHub `v3.0.0-beta.1`; Python metadata `3.0.0b1`

## 1. Decision

The first Public Beta must be installable from the immutable wheel and sdist attached to the GitHub Release. PyPI is an optional additional channel, not a prerequisite for Beta.

The release workflow must not upload to PyPI unless all of the following have separate authenticated evidence:

1. the exact project name and canonical normalization are confirmed in PyPI;
2. the repository maintainer has Owner or Maintainer permission for that project;
3. two-factor authentication is enabled for every publishing account;
4. a PyPI Trusted Publisher is bound to the exact GitHub repository, workflow and environment;
5. the workflow uses OpenID Connect and does not store a long-lived PyPI API token;
6. a non-production TestPyPI or equivalent dry-run has passed when appropriate;
7. the Release Checklist and `REL-005` evidence are updated without including credentials, recovery codes, session cookies or private account screenshots.

Until every condition is proven, the release workflow must have no enabled PyPI publish job and documentation must not advertise `pip install oh-my-deepseek-harness` from PyPI.

## 2. Public observations

Public exact-name searches performed on 2026-07-28 did not return an indexed project named `oh-my-deepseek-harness`. This is **not** treated as proof that the name is available: search indexes can be incomplete or stale, and reserved/hidden/account-level state is not public.

A different package named `deepseek-harness` is publicly indexed. It is not this project and must not be used as a fallback distribution identity. The project must never publish under a confusing substitute name without a new versioning/distribution decision.

## 3. Private facts not verified

The connected tools cannot inspect the maintainer's PyPI account, organization, 2FA, recovery codes, project roles or Trusted Publisher configuration. Therefore this Work ID does not claim:

- name ownership or reservation;
- Owner/Maintainer permission;
- 2FA status;
- Trusted Publisher existence;
- ability to publish successfully.

Absence of evidence is handled by disabling PyPI, not by guessing.

## 4. GitHub Release requirements

The mandatory Beta channel remains GitHub Release with:

- immutable tag pointing to the exact final verified commit;
- wheel and sdist rebuilt from that commit;
- `SHA256SUMS`;
- SBOM;
- artifact attestation/provenance;
- Release Notes and Known Limitations;
- public smoke installation from the attached artifact;
- no tag movement or artifact replacement.

`BETA-001` is the only Work ID authorized to create the first immutable Beta tag and Release after G3 and final-master artifact verification.

## 5. Future PyPI enablement

To enable PyPI later:

1. reopen `REL-005` or create an explicitly authorized publishing-prerequisite follow-up tied to this decision;
2. record only non-secret status fields:
   - normalized project name;
   - repository/organization ownership status;
   - role = Owner/Maintainer;
   - 2FA = enabled;
   - Trusted Publisher = configured;
   - workflow filename and protected GitHub environment;
   - verification date and verifier;
3. run a publish dry-run through `REL-006`;
4. update the Release Checklist and Known Limitations;
5. obtain explicit publication authorization at `BETA-001` execution time.

## 6. Security controls

- No PyPI password, API token, recovery code or session cookie may be stored in GitHub, documents, Issues, logs or artifacts.
- Prefer Trusted Publishing/OIDC and a protected GitHub environment.
- The publishing workflow must use least privilege and immutable artifacts generated by the release workflow.
- A failed PyPI upload must not create or alter the GitHub tag/Release identity.
- Public artifacts must never be replaced to hide a publishing error; publish a new prerelease when necessary.

## 7. Release impact

This decision removes an external-account blocker from G0 by choosing the supported fallback already allowed by the release plan: **GitHub-only Public Beta**. It does not authorize publication and does not prove that the product is Beta-ready.

M1 remains blocked until `COMPAT-000` and the separate G0 evidence decision are complete.
